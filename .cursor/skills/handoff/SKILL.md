# 다음 작업자가 바로 이어받는 인계 문서

다른 세션이나 다른 AI 도구가 이 문서와 작업 기록만 읽고 이어서 작업할 수 있게 한다. 인계 문서는 로컬 개인 자료이므로 커밋·push하지 않는다. 비밀값·쿠키·토큰·계정 정보는 쓰지 않는다.

## 위치와 커밋 금지

- 기록 저장소는 `docs/WORKLOG_POLICY.md`의 기록 위치 규칙을 따른다. 세션을 연 작업공간과 실제 작업 대상 저장소가 다르면 이 규칙으로 정한 같은 저장소의 `ai-input/`에 작업 기록과 인계를 함께 둔다.
- 경로는 `ai-input/handoff/YYYY-MM/YYYY-MM-DD-<제목>.md`다. 날짜는 실제로 확인한 KST 날짜를 쓴다. 본문 첫 제목에도 날짜와 제목을 넣는다.
- 작성 전에 위치가 Git 저장소 안이면 `git check-ignore -q <경로>`로 제외 여부를 확인한다. 제외되지 않으면 작성하지 않고 그 사실을 알린다. `git add -f`는 쓰지 않는다. Git 저장소 밖의 작업공간이면 상위 저장소가 없는지 확인하고 진행한다.

## 같은 작업은 갱신한다

- 쓰기 전에 `ai-input/handoff/` 전체에서 같은 작업 ID와 목표를 찾는다. 같은 작업이면 새 파일을 만들지 않고 원래 파일을 갱신한다. 파일 이름의 날짜는 처음 작성일로 유지한다.
- 갱신할 때는 본문을 현재 상태 기준으로 다시 쓴다. 맨 위에 "최신" 절을 계속 덧붙이지 않는다. 틀려진 설명은 고치거나 지우고, 중요한 상태 변화만 끝의 `변경 이력`에 날짜와 이유를 한 줄로 남긴다.
- 별도로 완료를 판단할 목표가 새로 생기면 새 파일로 쓰고 이전 인계 파일과 작업 ID를 연결한다.
- `ai-input/handoff/LATEST.md`에는 지금 먼저 읽을 인계 파일 링크, 기준 HEAD, 남은 필수 작업 유무, 이전 인계에서 틀려진 내용을 몇 줄로 둔다. 인계를 쓰거나 갱신할 때 함께 맞춘다.

## 쓰기 전에 현재 상태를 확인한다

기억이나 이전 문서를 옮겨 적지 않고 지금 확인한 값을 쓴다. 저장소·브랜치·HEAD SHA, `git status`, 열린 PR·CI, worktree·stash, 실행 중인 서버·백그라운드 작업, 작업공간 설정 경로를 확인한다. 임시 경로·세션 번호·서버 상태처럼 쉽게 바뀌는 값에는 확인 시각을 붙인다. 확인하지 못한 값은 미확인으로 쓴다.

## 본문 구성

필요한 절만 쓴다. 해당 내용이 없는 절은 "없음"으로 짧게 남긴다.

1. 현재 상태: 저장소·base·브랜치·HEAD SHA·PR·CI·실행 중 프로세스·작업공간.
2. 사용자 확정 사항: 결정 내용과 다시 제안하지 말아야 할 항목. 바꾸려면 사용자 확인이 필요하다고 적는다.
3. 남은 작업: 우선순위, 수용 기준, 사용자 결정이 필요한지 여부.
4. 알려진 결함과 미검증: 실제로 검증한 범위와 가짜 CLI·모의 자료로만 확인한 범위를 구분한다.
5. 하네스·스킬 결함: 작업 중 훅·스킬·지침 때문에 막히거나 우회한 내용과 재현 방법.
6. 작업 중 애로사항: 늦게 발견한 결함, 자주 난 오류, 속도·비용. 토큰·비용은 출처와 집계 범위를 적고 측정하지 않았으면 미측정으로 쓴다.
7. 다음 작업자 권고와 시작 방법: 먼저 읽을 파일, 확인 명령, 하지 말아야 할 일.

사실·추정·AI 제안·사용자 결정을 구분한다. 근거 파일과 작업 기록 ID를 링크한다.

## 마무리

- 같은 작업의 작업 기록에 인계 파일 경로를 남긴다.
- 작성 후 `git status --short`에 인계 파일이 나타나지 않는지 확인한다.
- 사용자에게는 인계 파일 경로와 남은 필수 작업만 짧게 알린다. 문서 전체를 대화에 다시 붙이지 않는다.
