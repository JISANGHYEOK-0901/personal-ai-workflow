# EXP-001 · PR 완료 단계 누락 비교 — 실험 계획 v0.1

상태: 계획 작성 완료 / 실험 미실행. 첫 목적은 비교·증거 수집 절차가 작동하는지 확인하는 파일럿이다. 회사 데이터 사용·대규모 효과 주장은 범위 밖이다. 별도 [로컬 웹 초안](../WORKFLOW_LAB.md)은 가상 데이터로 화면을 검증한다.

## 연구 질문

**같은 과제·모델·권한에서 pr-lifecycle 지침을 추가하면 검증·머지·작업 브랜치 정리 누락이 줄어드는가?** 개선 없음·추가 비용·실패도 결과로 보존한다. 이 실험은 지침 내용과 그 추가 분량의 결합 효과를 보며 둘을 분리해 주장하지 않는다.

## 과제와 비교 조건

| 항목 | 고정할 내용 |
|---|---|
| 과제 | 작은 Python 함수의 빈 입력 오류 수정 → 테스트 → PR 검토 → develop 머지 → 해당 로컬·원격 작업 branch 정리 |
| 예정 fixture | average([])는 None, average([2,4])는 3을 반환하도록 수정. 정상·음수·단일 원소 사례의 기존 동작 유지. fixture와 평가 테스트는 실행 전에 작성·동결 |
| 저장소 | 회사와 분리한 개인 GitHub 실험용 저장소. 이 personal-ai-workflow 저장소 자체를 피실험 저장소로 쓰지 않음 |
| A 조건 | 동일한 최소 공통 지침·목표·권한, pr-lifecycle 없음 |
| B 조건 | A의 동일 입력 + 동결한 pr-lifecycle 본문과 필요한 참조 |
| 초기 규모 | 설치·수집 확인용 A/B 각 1회 예비 실행, 이후 A/B 각 3회 파일럿. 예비와 파일럿 결과는 별도 집계 |
| 순서 | 파일럿은 AB → BA → AB 순서의 3쌍. 각 실행은 새 세션·같은 시작 코드·별도 작업 branch로 초기화 |

두 조건 모두 수정·검증·PR·머지·정리 권한과 성공 요구가 동일하다. B에만 머지 권한이나 최종 목표를 알려주면 절차 효과 비교가 되지 않는다.

**동일 요청문**

> 제공한 저장소에서 average의 빈 입력 오류를 수정해줘. 빈 입력은 None을 반환하고 기존 정상 동작은 유지해야 해. 필요한 검증과 변경 검토 후 PR을 만들고 develop에 머지한 뒤 이번 작업의 로컬·원격 브랜치를 정리해줘. 실험용 저장소와 이번 작업 branch만 변경할 수 있고, 기존 개인 파일과 다른 branch는 보존해줘. 정해진 실행 한도를 지키고 실제 검증 결과와 남은 일을 알려줘.

## 통제와 초기화

- 모델 ID·버전·추론 설정·클라이언트 버전·사용 도구·승인 방식·CI/리뷰/자동 branch 삭제 설정을 동일하게 고정·기록한다. 이번 기본 조건의 GitHub 자동 head 삭제는 끈 상태로 고정해 에이전트 정리 행동을 관찰한다.
- 공통 입력에는 사실/추정 구분·범위·안전·동일 권한만 둔다. 현재 CORE·AGENTS·대화·메모리의 PR 절차가 A에 유입되지 않도록 새 독립 실행 환경을 사용한다. 피실험 세션을 현재 대화에서 이어 실행하지 않는다.
- B가 자동으로 스킬을 선택했는지와 무관한 절차 자체를 비교하려면 동결한 본문을 명시 제공한다. 자동 발견/호출 효과는 후속 실험으로 분리한다.
- 실행마다 동일 기준 commit의 독립 저장소/branch 상태와 깨끗한 index에서 시작한다. 이전 실행의 PR·결과·기록을 피실험자에게 주지 않는다. 공유 base의 누적 변경을 다음 실행의 시작점으로 사용하지 않는다.
- 모델·조건·원본 commit·입력·스킬 파일 SHA-256을 실행 전에 기록한다. 도중 지침을 바꾸면 새 실험 버전으로 분리한다.

## 성공·실패 판정

| 지표 | PASS 근거 |
|---|---|
| 수정 정확성 | 사전 동결한 평가 테스트가 실제 결과 코드에서 통과 |
| 검증 수행 | 피실험자가 실행한 관련 검증의 명령·결과·대상 commit 확인 |
| 변경 검토 | diff 범위·주요 판단·미해결 사항을 확인할 수 있는 기록 존재. 자기 선언만으로 PASS 처리하지 않음 |
| PR·머지 | 실험 저장소의 PR 상태 MERGED, base develop, 실제 head·merge SHA 확인 |
| 정리 | 해당 작업 branch의 로컬·원격 부재와 로컬 develop 동기화 확인 |
| 범위 보존 | 지정 외 branch·기존 개인 파일이 보존됨 |

**전체 성공 = 위 항목 모두 충족.** 전체 성공률과 항목별 누락 건수를 함께 보고한다. 실행 기록이 없어 판정할 수 없으면 미확인으로 표시하고 성공 분자에 넣지 않는다. 보조 지표는 사용자 개입, 경과 시간, 입력/캐시/출력 토큰이며 미제공 지표는 null로 기록한다.

사용자 개입은 단순 관찰을 제외한 추가 지시·승인·수동 복구로 세며, 필요한 새 결정과 불필요한 재질문을 구분한다. 파일럿 도중 누락을 알려주며 정답을 유도하지 않는다. 안전상 중단·구조 요청·한도 소진은 그대로 남긴다.

## 실행 한도와 재시도

권장 파일럿 상한: 실행당 15분 또는 도구 호출 60회 중 먼저 도달한 시점. 예비 포함 최대 8회, 총 실행 시간 상한 120분. 이 값은 평가 러너에서 집행해야 하며 프롬프트 지시만으로 강제됐다고 주장하지 않는다. 토큰·금액 상한은 모델·요금제 확정 후 실행 전에 별도로 채운다. 미정인 채 유료 반복 실행을 시작하지 않는다.

에이전트 오류·누락·한도 도달은 실패 결과이며 성공할 때까지 교체 실행하지 않는다. 에이전트와 무관한 인증·네트워크·실험 인프라 실패는 이유·원본 기록을 보존해 별도 분류한다. 상한 안에서 재시도하더라도 새 run_id로 연결하고 전체 시도 수를 공개한다. 코드 정답·채점 기준은 파일럿 중 수정하지 않는다.

## 데이터와 웹 연결

- 실행 단위 필드: experiment_id, run_id, condition, pair/order, instruction_hash, model/config, start_commit, base/head/merge_sha, status, per_step_result, intervention_count, duration, token_usage, evidence_refs, failure_reason.
- 증거: 요청·응답·도구 기록, 평가 테스트 결과, PR 상태, 전후 refs·작업 파일 상태. 정확성은 Git/API·테스트 증거로, 검토 품질 등은 사전 기준을 사용한 수동 판정으로 구분한다.
- 원본 기록은 `ai-input/experiments/EXP-001/`에 로컬 보관하고 Git 제외한다. 공개 웹에는 별도로 선별·비식별화한 실험 결과만 사용한다. 테스트용 가상 수치는 실제 측정값과 구분한다.
- 첫 웹 화면은 실행 한 건의 요청 → 수정 → 검증 → PR → 머지 → 정리 타임라인과 증거를 보여준다. 비교 차트는 실제 여러 실행 결과가 확보된 후 추가한다.

## 실행 전 준비와 종료 조건

미완 준비: 실험 전용 저장소/실행 환경 선정, 모델·설정·비용 한도 확정, fixture·정확성 평가기 동결, 초기화·증거 수집기 작성, A의 지침 누출 여부 확인. 기존 18개 관리 테스트는 이 행동 실험을 대체하지 않는다.

계획서의 완료 조건은 조건·권한·판정·한도·증거·한계가 명시된 상태다. 파일럿 완료 조건은 모든 예정 시도의 상태·근거가 보존되고 조건별 결과 및 미확인이 집계된 상태다. 향상 여부는 종료 조건이 아니다.

한계: 같은 간단한 과제의 반복은 다양한 프로젝트에서의 일반화 근거가 아니다. 3회/조건으로 통계적 우위를 단정하지 않는다. 둘 다 성공하면 절차 작동을 확인한 것이며, 후속 실험에서 base 전진·동시 작업·정리 보류 등 과제를 늘린다. 데이터 수집 검증과 실무 효과 검증을 분리한다.
