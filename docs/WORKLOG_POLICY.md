# 개인 작업 기록

목적: 작업별 목표·결정·수행·결과를 나중에 분석한다. ly의 작업 ID 기반 갱신 방식을 참고하며, 이 프로젝트에 없는 wrapper·완료 게이트는 요구하지 않는다.

## 작업의 경계

- 하나의 독립된 목표와 산출물에 하나의 작업 ID를 부여한다. 관련 대화·질문·제안·검증은 같은 항목에 요약한다.
- 코드 변경 없는 조사·기획도 작업이다. 단순 확인, 진행 질문, 같은 목표 재정리는 새 작업이 아니다.
- 별도로 완료를 판단할 수 있는 목표·산출물이 생기면 새 작업으로 분리하고 관련 작업 ID를 적는다.
- 제안만 된 구현은 실행 작업으로 생성하거나 완료 처리하지 않는다. 기존 작업의 `AI 제안` 또는 `잔여`에 남긴다.

## 기록 시점과 갱신

- 완료·보류·중단·실패로 보고할 때, 중요한 범위·결정·상태 변화가 생길 때, 사용자가 기록을 명시 요청할 때 생성·갱신한다. 장기 작업은 의미 있는 중간 산출물이 생겼을 때 진행중으로 기록할 수 있다.
- 매 답변이나 도구 호출마다 기록하지 않는다. 같은 작업 ID는 기존 항목을 갱신하며 같은 상태·내용이면 무변경이다.
- 현재 상태·결정·결과는 최신으로 유지한다. 중요한 이전 결정과 상태 전이는 항목 안의 `주요 이력`에 시간·사유를 짧게 보존한다. 대화별 이벤트를 늘리지 않는다.
- `갱신 시각`은 내용이 실제 바뀔 때만 변경한다. `상태 변경 시각`은 실제 상태 전이 때만 변경한다. 소급 기록의 과거 시각은 미상이면 그대로 표시한다.

## 위치와 중복 방지

- `YYYY-MM/YYYY-MM-DD.md`: 월별 폴더 아래 최초 기록일(KST)의 날짜별 파일에 작업을 둔다.
- 날짜·월·세션이 바뀌어도 전체 월 폴더에서 작업 ID와 목표를 찾아 원래 항목을 갱신한다. 새 날짜 파일에 복제하지 않는다.
- ID는 `YYYYMMDD-slug`. 분리·통합 시 이전 ID와 대응 관계를 남긴다.
- ai-input/ 전체는 항상 Git에서 제외하며 강제 추가하지 않는다. 월 폴더의 기록은 로컬 개인 데이터다. 템플릿 배포 때 복사하지 않는다.

## 작업 형식

```markdown
## [프로젝트] 작업 요약 `id:YYYYMMDD-slug`
- AI 도구: codex / claude / 기타
- 상태: 진행중 / 완료 / 보류 / 중단 / 실패
- 최초 기록 시각:
- 갱신 시각:
- 상태 변경 시각: 실측값 또는 미상(소급 기록)
- 목표·범위:
- 사용자 확정:
- AI 제안:
- 수행·결과:
- 검증·증거:
- 커밋/PR: 없음 또는 링크
- 잔여:
- 주요 이력: 중요한 결정·상태 변화만 기록
```

상태는 작업 목표 기준이다. 답변 완료와 구현 완료를 혼동하지 않는다. 미측정 지표는 0이 아니라 미측정으로 쓰며, 토큰·비용은 출처와 집계 범위를 함께 적는다. 비밀값·쿠키·인증정보는 제외한다. 외부 대화는 사용자 제공과 직접 검증을 구분한다. 전체 채팅 원문·도구 출력 자동 수집이 아닌 세션의 지침 기반 요약 기록이다.
