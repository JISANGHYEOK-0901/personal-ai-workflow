# Workflow Lab · 로컬 초안

AI 개발 작업의 누락과 사람의 재확인을 관찰하고, 절차 개선 효과를 검증하는 도구다. 첫 사용자는 개인 개발자와 작은 개발팀으로 가정한다. 프로젝트 규모나 언어는 제한하지 않되 첫 실험은 작은 Python 과제로 수집 절차부터 확인한다.

## 현재 사용할 수 있는 것

```bash
python3 scripts/serve_lab.py
```

http://127.0.0.1:8765 에서 업무 현황 → 조건별 실행 선택 → 단계별 판정과 근거 → 업무 적용 가설을 본다. 외부 의존성 없는 HTML/CSS/JavaScript 초안이다. 서버는 지정한 웹 파일 3개만 제공한다. ai-input이나 저장소 전체를 정적 서버로 열지 않는다.

모든 실행과 시간·개입 수치는 가상이다. 실제 실험은 0회다. 데모 A/B 차이는 화면 설명을 위한 설정이며 효과의 증거가 아니다. 원본 로그 가져오기·자동 수집·공개 배포·실측 비교 차트는 아직 없다.

## 실험 준비물

[EXP-001 계획](experiments/EXP-001-pr-lifecycle.md)에 동일 요청·권한·판정 기준을 정의했다. `experiments/exp001/fixture/`에는 의도적으로 빈 입력 버그가 있는 함수와 정상 동작 테스트를 둔다. 외부 정확성 평가기는 다음과 같이 실행한다.

```bash
python3 experiments/exp001/evaluate.py experiments/exp001/fixture
```

기준 fixture에서는 빈 입력 오류로 종료 코드 1이 정상이다. 평가기는 지정 디렉터리의 Python 코드를 실행하므로 본인이 준비한 실험 코드에만 사용한다. 평가기 통과는 AI가 검증·리뷰·머지·정리했다는 증거가 아니며 해당 항목은 항상 unknown으로 남긴다. 별도 세션 격리, 초기화, Git/API 증거 수집과 시간·비용 제한을 구현한 실행기는 후속이다.

## 실무·사업 관점의 검증

- 문제: AI 작업 이후 검증·후속 처리를 사람이 다시 챙기는 부담.
- 해결 가설: 작업 절차와 근거를 함께 관리하면 누락·재작업을 줄일 수 있다.
- 측정: 항목별 누락, 수동 개입, 처리 시간, 모델 사용량·비용. 미측정은 0으로 채우지 않는다.
- 사업 가설: 효과가 반복 확인되면 기존 개발 도구에 연결하는 점검·보고 기능의 수요를 확인한다. 회사 도입·매출·절감액은 아직 성과가 아니다.
- 학습 연결: AI 평가, 실험 설계, 데이터 분석을 통해 어떤 조건에서 효과가 있는지 설명하는 것이 목표다. 특정 학교의 합격 기준이나 수익성 선호를 가정하지 않는다.

## 검증 범위

관리 테스트에 기준 버그 탐지·수정본 통과·AI 행동 미확인 유지, 웹 서버의 비공개 경로 접근 차단을 추가했다. 이는 실험 인프라 검증이며 실제 AI 행동 실험을 대체하지 않는다.
