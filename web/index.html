02 / 업무 적용 가설
더 적은 재확인, 설명할 수 있는 품질.
누구의 문제인가
AI로 개발하지만 검증과 후속 처리를 매번 직접 확인하는 개인 개발자와 소규모 개발팀.
어떻게 검증하나
동일 과제에서 절차 적용 전후의 누락, 사람의 개입, 처리 시간과 실행 비용을 비교합니다. 실패와 미확인도 보존합니다.
어디까지 확장하나
효과가 확인되면 기존 개발 도구에 연결하는 작업 점검·보고 기능을 검토합니다. 회사 도입과 유료화는 아직 가설입니다.
면접에서 설명할 프로젝트 이야기
실무에서 AI의 코드 작성 이후 검증과 정리까지 사람이 재확인하는 문제에 주목했습니다. 작업 절차와 관찰 도구를 만들고 개인 환경에서 개선 효과를 측정하려 합니다. 대학원에서는 AI 평가와 데이터 분석을 배워 효과가 나타나는 조건과 한계를 더 정확히 검증하고 싶습니다.
측정한 사실과 기대 효과를 분리합니다. · 원본 작업 기록은 공개하지 않습니다.
