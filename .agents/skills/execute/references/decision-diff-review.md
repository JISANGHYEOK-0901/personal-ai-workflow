# 결정 분류와 diff 검토

진행 장애를 무조건 사용자 질문으로 바꾸거나, 자율성을 이유로 중요한 결정을 대신하지 않기 위한 공통 게이트다. `execute`의 변경 작업과 `pr-lifecycle`의 PR 검토에서 사용한다.

## 1. 사실·결정·차단을 구분한다

| 분류 | 기준 | 행동 |
|---|---|---|
| 확인 가능한 사실 | 코드·문서·설정·도구 조회나 안전한 재현으로 확인 가능 | 직접 조사하고 결과를 사용한다. 실행 방법 선택을 사용자에게 넘기지 않는다. |
| MINOR 결정 | 승인 범위 안이고 쉽게 되돌릴 수 있으며 다른 결정·외부 상태를 구속하지 않음 | 기존 관례와 권장안을 적용해 진행한다. 결과에 영향을 주면 결정과 근거를 작업 기록이나 관련 정본에 남긴다. |
| MAJOR 결정 | 되돌리기 어렵거나 다른 선택을 구속함. 제품 동작·공개 계약·데이터·인증/보안·비용·배포·외부 쓰기·권한 범위를 바꿈 | 의존 실행 전에 영향과 권장안을 제시해 사용자 결정을 받는다. 독립 작업은 계속한다. |
| BLOCKER | 필요한 권한·자격정보·자료·외부 상태가 없거나, 허용된 시도 안에서 필수 증거를 얻을 수 없어 목표 진행이 실제로 불가능함 | 막힌 조건, 수행한 확인, 보존한 결과, 재개 조건을 보고한다. 모호함이나 아직 하지 않은 조사를 BLOCKER로 부르지 않는다. |

불확실하면 먼저 조사한다. 조사 뒤에도 MINOR 기준을 충족하는지 불명확하면 MAJOR로 다룬다. 이미 받은 결정과 승인은 재사용한다. 사용자가 정한 시간·비용·시도 budget은 중단 조건이며 권한 확대, 결정 등급 하향, 성공 판정의 근거가 아니다.

## 2. 검토 기준을 정한다

- Git 작업은 작업 시작 상태나 PR의 실제 base와 현재 head를 이름이 아닌 SHA로 식별한다. 시작부터 dirty였다면 사용자 변경과 이번 작업 변경을 구분한다.
- PR은 실제 base/head와 merge-base를 확인한다. base가 움직였으면 최신 통합 결과에 대한 기존 검토·검증의 유효성을 다시 판단한다.
- index, worktree, 관련 미추적 파일을 모두 포함한다. `git diff` 하나만으로 staged·unstaged·untracked 상태를 모두 봤다고 주장하지 않는다.
- Git이 아닌 작업은 수정 전 자료와 최종 산출물 또는 그에 준하는 명시적 비교 기준을 사용한다. 존재하지 않는 SHA나 diff를 만들지 않는다.
- 상태·파일 목록·요약으로 범위를 잡은 뒤 실제 patch와 관련 미추적 파일 내용을 읽는다. 비밀값·개인 데이터는 출력이나 기록에 노출하지 않는다.

명령은 저장소와 상황에 맞게 선택한다. 흔히 `git status --short`, `git diff --stat`, `git diff --name-status`, 실제 patch, staged diff가 서로 다른 증거를 제공하지만 이 명령 목록 자체를 고정 체크리스트로 만들지 않는다.

## 3. 의미를 검토한다

최종 diff의 각 변경 경로를 사용자 요구, 기결정, 또는 요구를 만족하는 데 필요한 지원 변경에 연결한다. 연결되지 않는 변경은 범위 밖인지 확인하고 분리하거나 되돌릴 안전한 방법을 선택한다.

변경 영향에 따라 다음을 살핀다.

- 예상하지 않은 파일·삭제·rename, 생성물·lock/vendor 파일, 임시 로그·디버그 코드·TODO, 비밀값·개인 데이터
- API·이벤트·공유 타입·DB/저장 데이터·인증·권한·의존성·설정·CI·배포 계약과 생산자/소비자, 하위 호환성
- 정상·실패·경계 동작, 사용자에게 보이는 문구와 흐름, 오류 처리
- 테스트가 실제 변경 동작과 실패 경로를 확인하는지, 미검증 영향이 무엇인지

검사 명령 성공과 diff 의미 검토를 구분한다. 발견한 MINOR 결함은 승인 범위에서 수정하고 영향받은 검증과 최종 diff를 다시 확인한다. MAJOR 결정이나 BLOCKER에 의존하는 commit·push·머지·배포는 진행하지 않는다.

## 4. 검토 증거를 남긴다

작업 영향에 맞춰 다음을 작업 기록, PR 본문, 또는 최종 보고에 남긴다.

- 검토 기준: 저장소/대상, base·head SHA 또는 비-Git 비교 기준, dirty 상태의 소유 구분
- 검토 범위: 변경 경로와 확인한 계약·소비자·외부 영향
- 발견 사항: BLOCKER/MAJOR/MINOR 분류, 수정 또는 사용자 결정 결과, 미해결 사항
- 검증: 실행한 명령·대표 동작과 결과, 미실행·검토 불가 범위

근거가 없는 `diff 검토 완료` 선언이나 자체 점수는 증거가 아니다. 의미적 검토는 에이전트 판단이므로 파일 동기화·정규식 검사·단일 합성 사례만으로 모든 작업에서의 준수를 입증하지 않는다.
