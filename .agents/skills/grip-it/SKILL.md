# Grip-it 결정 인터뷰

구현에 영향을 주는 결정을 착수 전에 사용자와 확정한다. [결정 기록부와 편집 훅](references/register.md)에 기록 형식과 경로가 있다.

## 조사와 전체 목록

1. 실제 작업 대상과 참조할 자료를 확인한다. 요청·기존 명세·결정 기록에서 목적과 성공 조건, 범위와 산출물, 사용자가 정리하고 싶은 방향을 파악한다. 조사로 확인할 사실을 먼저 확인하고 기결정은 재사용한다. 목적이나 범위가 빠져 토픽을 판정할 수 없을 때는 필요한 전제만 물은 뒤 목록을 만든다.
2. 같은 대상과 작업의 기록부가 있으면 이어서 사용한다. 새 작업은 [기록 형식](references/register.md)으로 기록부를 먼저 만든다. 범위 내 미결 토픽 전체를 안정적인 ID, 중요도, 선행 토픽과 함께 사용자에게 보여준다. 되돌리기 어렵거나 다른 결정을 구속하면 `CORE`, 가역적이면 `MINOR`로 기록한다. 사용자의 선택이 필요한 항목을 질문하고, 직전 목록의 이미 확정된 선택은 반복하지 않는다.
3. 목록에는 권장 순서와 진척을 보여준다. 예를 들어 `RESOLVED 0 / DROPPED 0 / TOTAL 2`를 표시하고, 기본 최종 검토자 결정에 검증실의 개입 조건이 의존한다면 그 관계를 밝힌다.

## 한 토픽씩 결정과 반영

1. 선행 결정이 해소된 첫 미결 토픽만 묻는다. 결정의 영향과 권장안의 이유를 짧게 설명한다. 선택형 질문 도구가 있으면 한 토픽에만 사용한다. 권장안을 처음에 두고 실제 대안과 직접 입력 방법을 제시한다. UI에 자유 입력이 있으면 그 입력을 이용한다. 도구가 없으면 채팅에 같은 선택지를 제시하고 답을 기다린다. 결정에 필요한 전문용어는 질문 근처에서 풀어 쓴다.
2. 사용자 답이 오면 선택·이유를 관련 근거 문서에, 이후 작업에 적용할 내용은 관련 명세나 지침에 반영한다. 이미 존재하는 정본을 우선 사용하고 다른 문서에는 필요한 참조만 남긴다. 문서 변경은 사용자와 합의된 범위에서 한다. 두 역할을 같은 정본이 맡으면 그 파일을 사용한다. 반영한 위치와 결정 내용을 기록부에 남기고 `RESOLVED`로 바꾼다. 자료 반영이 막혔다면 남은 일을 기록하고 그에 의존하는 작업을 기다린다.
3. 사용자가 토픽을 제외하면 이유와 함께 `DROPPED`를 적고 기존 토픽 ID·총개수를 유지한다. 새 결정으로 후속 토픽의 의미나 의존 순서가 바뀌면 목록을 갱신하고 변경 이유를 알려준다. 다음 질문 전에 직전 결정의 반영 위치와 갱신된 진척을 사용자에게 보여준다.

## 실행 전환과 재개

- 결정에 의존하는 구현과 외부 실행은 해당 선택이 확정·반영된 뒤 시작한다. 범위가 분명한 독립 조사·준비는 진행할 수 있다. 설치된 편집 훅을 사용할 때는 확실히 의존하는 파일 경로를 기록부에 등록한다.
- 새 세션에서 재개할 때는 기록부와 참조된 정본을 읽는다. 확정·제외된 토픽을 유지하고 첫 진행 가능한 미결 토픽으로 돌아간다. 확정 내용과 현재 정본이 달라졌다면 변경 근거를 먼저 확인한다.
- 인터뷰가 끝나면 확정한 선택, 반영 위치, 남은 항목을 짧게 전한다. 구현 요청도 받았다면 확정 범위와 기록부를 `execute`에 이어 넘긴다.
